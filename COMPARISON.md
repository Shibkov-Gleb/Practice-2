# Сравнение визуализации с npm

Проверено 13 ноября 2026 года: Python 3.9.6, Node.js 24.19.0, npm 11.6.2,
D2 0.9.0, реестр `https://registry.npmjs.org`. Все запросы и сравнения выполнены,
диаграммы просмотрены после растеризации SVG. Это фактический результат запуска,
а не предполагаемый вывод. `latest` в реестре со временем меняется.

## Методика

Приложение самостоятельно запрашивает метаданные через HTTP, строит граф BFS,
формирует D2 и запускает D2 для получения SVG. npm не участвует в его работе.

Для каждого пакета отдельно создан временный `package.json` с единственной
зависимостью `<package>: latest`. Штатное дерево получено командами:

```sh
npm install --package-lock-only --ignore-scripts --no-audit --no-fund \
  --registry=https://registry.npmjs.org
npm ls --all --package-lock-only --omit=dev --unicode=false
npm ls --all --package-lock-only --omit=dev --json
```

Пакетные скрипты не исполнялись; установка файлов пакетов не требовалась.
Сравнивались имена вершин и направленные рёбра логического дерева, без
искусственного корня `practice2-comparison`. Данные приложения и npm получались
независимо. Реализация и повтор запуска: `make compare-npm`, `tools/compare_npm.py`.
При отдельном расположении npm задайте `NPM_BIN`; Node.js должен быть в `PATH`.
В этой среде использованы bundled Node.js и официальный npm CLI из временного каталога.

| Пакет | Узлы | Рёбра | Имена и рёбра совпали с npm | Изображение |
| --- | --- | --- | --- | --- |
| `is-number` | 1 | 0 | Да | `output/is_number.svg` |
| `is-odd` | 2 | 1 | Да | `output/is_odd.svg` |
| `@types/node` | 2 | 1 | Да | `output/types_node.svg` |

Во всех трёх случаях множества рёбер, присутствующих только у одного инструмента,
пусты. Рядом с каждым SVG сохранён соответствующий D2. ASCII приложения:

```text

is-odd

@types/node

```

Вывод `npm ls` после удаления только временного абсолютного пути:

```text
practice2-comparison@1.0.0

practice2-comparison@1.0.0
`-- is-odd@3.0.1
  `-- is-number@6.0.0

practice2-comparison@1.0.0

  `-- undici-types@8.9.0
```

Полный локальный протокол с путями временных проектов: `output/comparison.md`.
Сгенерированные изображения и протокол игнорируются Git как артефакты;
команды воспроизводят их после клонирования. Этот отчёт хранится в Git.

## Расхождения и их причины

Имена пакетов и рёбра совпадают, но модели версий различаются. Для зависимости
`is-odd → is-number` npm выбрал `is-number@6.0.0` согласно диапазону, объявленному
в `is-odd`. Приложение для любого имени запрашивает `latest`; при отдельной
проверке `is-number` это `7.0.0`. В обеих версиях у is-number нет зависимостей,
поэтому в данном примере это не изменило структуру графа.

Приложение показывает имя пакета один раз, а npm строит дерево разрешённых
версий и может показывать несколько версий одного имени. Здесь такой ситуации
нет. Приложение не разрешает semver, Git/URL-спецификации и npm-алиасы.
Также оно включает объявленные optional-зависимости независимо от платформы,
не добавляет peer/dev-зависимости и применяет пользовательский фильтр.
В других пакетах эти отличия могут менять состав графа.

SVG использует размещение D2 и стрелки, а `npm ls` — текстовое дерево с версиями.
Это различие представления. Отступы и корень временного проекта не считаются
различием зависимостей. Для общих узлов ASCII приложения использует `[seen]`,
для циклов `[cycle]`; полный набор рёбер сохраняется в D2/SVG.

Официальные описания: [D2](https://d2lang.com/tour/intro/),
[npm ls](https://docs.npmjs.com/cli/v11/commands/npm-ls/),
[поля package.json](https://docs.npmjs.com/cli/v11/configuring-npm/package-json/).
