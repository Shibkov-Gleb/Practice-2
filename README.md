# Практическая работа 2 — вариант 30, этапы 1–5

Инструмент анализа и визуализации графа зависимостей npm на Python.
Настройки загружаются из XML; зависимости извлекаются собственным HTTP-кодом
на стандартной библиотеке (`urllib`, `json`). Транзитивный граф строится BFS
без рекурсии, с фильтрацией и поддержкой циклов. Результат: текст D2, SVG и,
по настройке, ASCII-дерево. Для этапа 4 доступен обход обратных зависимостей.

## Требования и быстрый запуск

Нужны Python **3.9+** и [компилятор D2](https://d2lang.com/tour/install/).
D2 используется только для рисования уже полученного графа. Для анализа
не используются npm, Node.js или сторонние библиотеки получения зависимостей.

Поиск компилятора: переменная окружения `D2_BIN`, затем `d2` в `PATH`, затем
`~/.local/bin/d2`. В рамках выполнения работы D2 0.9.0 установлен в последний
каталог. `D2_BIN` задаёт расположение внешнего инструмента, а не настройки анализа.

```sh
./run.sh --config examples/test_config.xml
./run.sh --config examples/test_cycle.xml
./run.sh --help
mkdir -p output
./run.sh --config examples/visual_is_odd.xml
```

`run.sh` самостоятельно переходит в каталог проекта. Если исполняемый бит
потерян, используйте `sh run.sh`. Для выбора Python: `PYTHON=python3 sh run.sh ...`.
Эквивалентный запуск модуля из корня проекта:

```sh
python3 -B -m src.main --config examples/test_config.xml
```

`--config FILE` обязателен. Его путь определяется относительно каталога запуска.
Все пользовательские настройки анализа берутся только из XML. Опций для их
переопределения нет. `--help` не требует XML, сети или D2.

## Все настройки

```xml
<?xml version="1.0" encoding="UTF-8"?>
<config>
    <package>is-odd</package>
    <repository>https://registry.npmjs.org</repository>
    <test_mode>false</test_mode>
    <output_file>../output/is_odd.svg</output_file>
    <ascii_tree>true</ascii_tree>
    <filter_substring></filter_substring>
</config>
```

| Поле | Назначение |
| --- | --- |
| `package` | Имя npm-пакета, включая `@scope/name`, или тестового пакета. |
| `repository` | HTTP(S)-URL реестра либо читаемый файл JSON при тестовом режиме. |
| `test_mode` | Только `true` или `false`; выбирает JSON или собственный HTTP-клиент. |
| `output_file` | SVG-файл. Рядом сохраняется одноимённый файл с расширением `.d2`. |
| `ascii_tree` | Только `true` или `false`; управляет печатью ASCII-дерева. |
| `filter_substring` | Исключение по регистрозависимой подстроке; пустая строка отключает фильтр. |

Все шесть элементов обязательны, даже пустой фильтр. Пробелы по краям значений
удаляются. Неизвестные и повторные поля, атрибуты, вложенные элементы и лишний
текст отклоняются. XML-комментарии допустимы. Только фильтр может быть пустым.

Имя пакета проверяется по допустимым буквам, цифрам и символам `._-`, с возможной
областью `@scope/`. URL проверяется без сетевого запроса: схема HTTP(S), DNS-имя
или IP, порт, отсутствие пробелов и учётных данных. DNS-метки и длины проверяются.
Тестовый путь должен вести к читаемому файлу. Пути к репозиторию, SVG и D2
разрешаются относительно **каталога XML**, а не текущего каталога процесса.

Расширение изображения — `.svg` без учёта регистра. Каталог назначения должен
существовать и разрешать запись; каталог на месте файла недопустим. Значения
вроде `graph.svg/` отклоняются. XML и тестовый репозиторий защищены от перезаписи
выходными D2/SVG. Фильтр и пути не должны содержать непечатных символов.

## Модель npm и BFS

Запрос метаданных: `repository/<encoded-package>/latest`. Для scoped-пакетов
слеш экранируется; базовый путь и query URL сохраняются. HTTP timeout — 10 секунд.
Обрабатываются HTTP-ошибки, сетевые сбои, обрыв ответа, неправильный JSON,
несоответствие имени и некорректные поля зависимостей.

Анализируются `dependencies` и `optionalDependencies`; при совпадении ключей
приоритет у `optionalDependencies`. `devDependencies` и `peerDependencies`
не включаются. Это граф **по именам пакетов с метаданными latest** для каждого
узла. Разрешение semver-диапазонов, npm-алиасов, Git/URL-зависимостей и lockfile
не реализовано. Результат не является точной моделью конкретной установки npm.
Различия с менеджером пакетов разобраны в [COMPARISON.md](COMPARISON.md).

Очередь `deque`, `popleft()` и множество обнаруженных вершин обеспечивают BFS
без рекурсии. Соседи сортируются и очищаются от повторов. Исключённый пакет
не загружается, его поддерево не обходится. Общий узел остаётся доступен через
другой неисключённый путь. Циклические рёбра и самоссылки сохраняются в графе,
но узел загружается не более одного раза. Исключение корня даёт пустой граф.

## Тестовый репозиторий и примеры

```json
{"A": ["B", "C"], "B": ["D"], "C": ["D"], "D": []}
```

Каждый ключ и ссылка состоят из заглавных латинских букв `A-Z`; многобуквенные
имена допустимы. Значение — список имён. Все ссылки должны иметь ключи, включая
листья. Дубли JSON-ключей, неверная структура и необъявленные ссылки отклоняются
во всём репозитории, даже вне достижимой компоненты. Циклы и общие узлы допустимы.
Тестовый режим не обращается к сети.

| XML в `examples/` | Сценарий |
| --- | --- |
| `test_config.xml` | Простой граф A → B, C. |
| `test_diamond.xml` | Общая транзитивная зависимость D. |
| `test_cycle.xml` | Цикл A → B → C → A и самоссылка D. |
| `test_filter.xml` | Исключение B из ромба. |
| `test_empty.xml` | Изолированный A. |
| `test_filtered_root.xml` | Исходный пакет исключён. |
| `config.xml` | Реальный express, фильтр debug. |
| `no_dependencies.xml` | Реальный is-number. |
| `scoped_config.xml` | Реальный @types/node. |
| `visual_is_number.xml`, `visual_is_odd.xml`, `visual_types_node.xml` | Три SVG и ASCII-дерева. |

```sh
make demo-errors
make demo-graphs
make demo-reverse
make demo-visuals
```

`demo-errors` демонстрирует ошибки всех шести настроек. `demo-graphs` выполняет
шесть локальных сценариев. `demo-visuals` требует сеть и D2, создаёт каталог
`output/` и три пары D2/SVG. Сгенерированные файлы игнорируются Git как артефакты.

## Обратные зависимости: этап 4

```sh
python3 -B -m src.reverse --config examples/reverse_diamond.xml
make reverse
make demo-reverse
```

Операция использует те же шесть настроек XML; точка входа выбирает режим.
В тестовом режиме разворачиваются рёбра **всего** репозитория, включая узлы,
недостижимые прямым обходом от выбранного пакета. Затем запускается тот же BFS
этапа 3 с фильтром. Вывод включает прямые и транзитивные зависимые пакеты,
каждый один раз; исходный пакет не печатается в списке при наличии цикла.

Для D в ромбе результат: B, C, A. С фильтром B: C, A. Конфигурации
`reverse_diamond.xml`, `reverse_cycle.xml`, `reverse_empty.xml`, `reverse_filter.xml`
демонстрируют ромб, цикл, отсутствие зависимых пакетов и фильтрацию.

Для npm область операции — загруженный достижимый граф, **не весь публичный
реестр**. Это ограничение явно выводится в CLI. Метаданные пакета не содержат
полного списка всех его потребителей. Для полного обратного поиска по заданному
набору пакетов используйте JSON со всем этим набором.

## Визуализация: этап 5

Каждому имени назначается безопасный идентификатор `n0`, `n1`, …; имя становится
экранированной подписью D2. Определяются все вершины, включая изолированные,
и все направленные рёбра, включая циклические и самоссылки. Пустой граф получает
подпись об исключении корня. D2 компилируется с layout `dagre`, без shell,
с timeout 60 секунд. Проверяются код возврата и корректность корневого SVG-тега.

D2 и SVG сначала создаются во временном каталоге рядом с результатом.
Ошибка компиляции не заменяет существующие выходные файлы. После успешной
проверки каждый файл заменяется отдельной операцией rename. Замена двух файлов
не является единой файловой транзакцией при сбое диска между операциями.
Временные файлы удаляются автоматически, в том числе при ошибках.

При `ascii_tree=true` после путей D2/SVG печатается дерево:

```text
A
|-- B
|   `-- D
`-- C
    `-- D [seen]
```

Используются только ASCII-ветви `|--`, `` `-- ``; `[cycle]` отмечает возвращение
в текущий путь, `[seen]` — уже раскрытый общий узел. Оба случая прекращают
повторное раскрытие. Сам вывод дерева тоже нерекурсивный. При `false` печатаются
только пути D2/SVG. На этапе 5 автоматически не печатаются ни настройки этапа 1,
ни список прямых зависимостей этапа 2, ни обратный список этапа 4.

Ошибка XML/настроек возвращает код 2. Ошибка данных или визуализации — код 1,
сообщение в stderr без traceback и частичного успешного stdout. Успех — код 0.

## Сравнение со штатным npm

npm и Node.js требуются **только для независимого сравнения**, не для приложения.
Команда создаёт временные проекты без исполнения пакетных скриптов:

```sh
make compare-npm
```

`NPM_BIN` может задавать путь к npm CLI. Используются `npm install
--package-lock-only --ignore-scripts --no-audit --no-fund` и `npm ls --all
--package-lock-only --omit=dev`, отдельно с `--json` и `--unicode=false`.
Сравниваются множества имён и направленных рёбер после удаления искусственного
корня временного проекта. Временные проекты удаляются. Протокол сохраняется
в `output/comparison.md`; подтверждённые результаты и объяснения расхождений
приведены в [COMPARISON.md](COMPARISON.md). Версии latest могут со временем измениться.

## Ветки и коммиты

| Ветка | Рабочее состояние |
| --- | --- |
| `codex/stage-1` | XML-прототип, вывод ключ–значение, ошибки настроек. |

Каждая следующая ветка продолжает предыдущую. Каждый этап сохранён отдельным
подробным Conventional/Scoped Commit; исправления первых этапов уже находятся
в соответствующих коммитах. `main` указывает на итог этапа 5.

```sh
git switch codex/stage-1
make test check
git switch codex/stage-5
make test check
```

Сохранена резервная ветка прежней истории
`backup/before-stage-fixup-2026-10-30`. Ветки и коммиты созданы локально.
Публикация изменений и очная защита остаются организационными требованиями:
пользователь разрешил локальные коммиты; удалённая история не менялась.

## Сборка, тестирование и оформление

```sh
make build
make test
make check
python3 -m pip install -r requirements-dev.txt
make lint
make audit
sh -n run.sh
git diff --check
```

`build` проверяет компиляцию Python и создаёт игнорируемые `.pyc` рядом с исходниками.
`check` проверяет ограничения PDF через AST и длины строк.
`audit` проверяет структуру, документацию функций, файлы Git и ветки этапов. Flake8 с pep8-naming
проверяет PEP 8, импорты, имена и McCabe; `.flake8` задаёт 79 символов, сложность 10
и исключает только W503, конфликтующее с современным переносом перед оператором.
Остальные стандартные исключения Flake8 не скрывают проверки.

Docstring и комментарии ограничены 72 символами, файлы — 1000 строками,
функции — 40 строками и 7 аргументами; числовые литералы в сравнениях запрещены.
Документация функций оформлена docstring. Нужные unittest имена `setUp` сохранены.
Проверка применимых рекомендаций PEP 8 включает ручной просмотр, не только линтер.

Модульные тесты используют стандартную библиотеку и подменяют внешние процессы.
Две проверки реального CLI/SVG пропускаются, если D2 не найден. При выполнении
работы они пройдены с настоящим D2. Для выбора Python: `make test PYTHON=python3`.
Полная сверка требований, результаты и организационные ограничения: [AUDIT.md](AUDIT.md).

## Структура и справочник всех функций

`src/` — приложение; `tests/` — проверки; `tools/` — проверки оформления,
демонстрации и независимое сравнение; `examples/` — XML и JSON. Есть `run.sh`,
`Makefile`, `.gitignore`, `.flake8`, `requirements-dev.txt`. Бинарные инструменты,
архивы, SVG, D2, кэши, `.pyc` и настройки редакторов в Git не добавляются.

Ниже перечислены все явно объявленные классы и функции текущей версии,
включая внутренние функции, методы тестов и служебные команды. Типы параметров
и возвращаемых значений указаны в исходниках рядом с docstring. `Config` содержит
ровно шесть описанных настроек; `DependencyGraph` — словарь имён и кортежей соседей,
`DependencyLoader` — функция получения соседей. В `src` публичный API задан `__all__`.

### `src/__init__.py`

Инструмент анализа зависимостей npm: вариант 30, этапы 1-5.

### `src/ascii_tree.py`

Нерекурсивное ASCII-представление графа зависимостей.

- `format_ascii_tree` — Показать цикл и общий узел, не раскрывая их повторно.

- `_push_children` — Положить детей на стек в обратном порядке для прямого вывода.

- `_reference_suffix` — Отличить замыкание текущего пути от общей зависимости.

### `src/config.py`

Загрузка шести параметров первого этапа из XML-файла.

- `Config` — Проверенные настройки приложения, неизменяемые после загрузки.

- `load_config` — Прочитать XML и проверить параметры относительно его каталога.

- `_read_fields` — Проверить структуру XML, обязательные и повторяющиеся поля.

- `_validate_root` — Проверить имя корневого элемента и отсутствие лишнего текста.

- `_validate_element` — Запретить вложенные элементы, атрибуты и лишний текст.

- `_build_config` — Преобразовать строки в проверенные настройки.

### `src/graph.py`

Итеративное построение графа зависимостей обходом в ширину.

- `build_dependency_graph` — Построить достижимый граф BFS, сохранив рёбра циклов.

- `_filter_dependencies` — Отсортировать уникальные имена после фильтрации.

- `_is_excluded` — Проверить непустую подстроку с учётом регистра.

- `format_graph` — Представить граф списками смежности в порядке обхода BFS.

### `src/main.py`

CLI пятого этапа: XML, граф BFS, D2/SVG и ASCII-дерево.

- `create_parser` — Создать CLI с опцией выбора XML-конфигурации.

- `main` — Построить граф по настройкам и вернуть код результата.

### `src/npm.py`

Получение прямых зависимостей через HTTP API реестра npm.

- `DependencyError` — Ошибка получения или разбора метаданных пакета npm.

- `build_metadata_url` — Дополнить URL реестра именем пакета и тегом latest.

- `fetch_direct_dependencies` — Получить прямые runtime-зависимости latest без обхода графа.

- `_read_metadata` — Выполнить HTTP-запрос и преобразовать JSON-ответ в объект.

- `_validate_metadata` — Проверить имя и версию в метаданных, полученных от реестра.

- `_extract_section` — Прочитать и проверить словарь зависимостей одного типа.

- `_validate_specification` — Проверить строковый формат диапазона или адреса зависимости.

### `src/presentation.py`

Вывод результатов пятого этапа и защита входных файлов.

- `present_graph` — Сохранить граф и при необходимости добавить ASCII-дерево.

- `_protect_inputs` — Защитить XML и локальный репозиторий от перезаписи.

### `src/repository.py`

Источники зависимостей: реестр npm или локальный тестовый граф.

- `create_dependency_loader` — Выбрать источник данных, сохранив пути относительно XML.

- `load_test_repository` — Прочитать JSON-граф и проверить его структуру и ссылки.

- `_unique_pairs` — Запретить повторяющиеся ключи в JSON-описании репозитория.

- `_validate_test_repository` — Проверить списки зависимостей и наличие всех упомянутых узлов.

- `_validate_test_name` — Разрешить имена из одной или нескольких заглавных букв A-Z.

- `_test_dependencies` — Получить зависимости из проверенного тестового графа.

### `src/reverse.py`

Обратный граф и отдельный CLI-режим четвёртого этапа.

- `reverse_graph` — Развернуть все рёбра, сохранив также изолированные вершины.

- `find_reverse_dependencies` — Обойти входящие рёбра тем же нерекурсивным BFS третьего этапа.

- `_load_graph` — Взять весь тестовый репозиторий или достижимый граф npm.

- `_format_reverse` — Показать прямые и транзитивные зависимости в порядке BFS.

- `main` — Запустить дополнительную операцию над известным графом.

### `src/validation.py`

Проверка пользовательских параметров без сетевых запросов.

- `ConfigError` — Ошибка чтения или проверки конфигурации.

- `validate_package` — Проверить простое либо scoped-имя пакета без пробелов.

- `parse_boolean` — Преобразовать строго true или false в логическое значение.

- `resolve_path` — Разрешить путь относительно каталога XML-конфигурации.

- `validate_repository` — Проверить URL либо доступность файла в тестовом режиме.

- `_validate_url` — Проверить синтаксис HTTP(S)-адреса и диапазон порта.

- `_validate_hostname` — Проверить DNS-метки; IPv6 уже проверен функцией urlsplit.
