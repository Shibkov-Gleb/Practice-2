
# Практическая работа 2 — вариант 30, этапы 1 и 2

CLI-инструмент получения прямых зависимостей npm. Реализованы загрузка и
проверка шести настроек из XML (этап 1), получение метаданных из npm-реестра
по HTTP(S) и вывод всех прямых runtime-зависимостей (этап 2).

Используется только стандартная библиотека Python: `urllib.request` для HTTP,
`json` для разбора ответа. Менеджеры пакетов, сторонние библиотеки получения
зависимостей, Node.js и установленный npm не требуются.

Список параметров `ключ=значение` выводился только на первом этапе; теперь
приложение выводит прямые зависимости. Обход графа, транзитивные зависимости,
фильтрация, ASCII-дерево и создание изображения пока не реализуются.
Чтение тестового графа относится к этапу 3: при `test_mode=true` приложение
возвращает понятную ошибку без сетевого запроса. Проверка самой XML-конфигурации
и доступности файла тестового репозитория сохранена.

## Требования и запуск

Python **3.9 или новее**. Установка дополнительных пакетов не нужна.
Команды выполняются из корня проекта, если не указано иное.

```sh
python3 -B -m src.main --config examples/config.xml
```

Скрипт запуска самостоятельно переходит в каталог проекта:

```sh
./run.sh --config examples/config.xml
./run.sh --config examples/scoped_config.xml
./run.sh --config examples/no_dependencies.xml
./run.sh --help
```

Если исполняемый бит не сохранился, используйте `sh run.sh` с теми же опциями.
Переменная окружения `PYTHON` позволяет выбрать интерпретатор для `run.sh`:

```sh
PYTHON=python3 sh run.sh --config examples/config.xml
```

Опция `--config FILE` обязательна и выбирает XML-файл. Путь `FILE` определяется
относительно текущего каталога запуска. Все шесть пользовательских настроек
берутся исключительно из XML; опции для их переопределения отсутствуют.
Опция `--help` выводит справку.

## Конфигурация

```xml
<?xml version="1.0" encoding="UTF-8"?>
<config>
    <package>express</package>
    <repository>https://registry.npmjs.org</repository>
    <test_mode>false</test_mode>
    <output_file>graph.svg</output_file>
    <ascii_tree>true</ascii_tree>
    <filter_substring>debug</filter_substring>
</config>
```

| Параметр | Назначение и проверка |
| --- | --- |
| `package` | Имя пакета: `express`, `@scope/name` или `A` для тестов. |
| `repository` | HTTP(S)-адрес; при `test_mode=true` — читаемый локальный файл. |
| `test_mode` | Строго `true`/`false`; для получения данных на этапе 2 нужно `false`. |
| `output_file` | Имя будущего изображения с расширением `.svg`. |
| `ascii_tree` | Настройка будущего вывода ASCII-дерева: `true` или `false`. |
| `filter_substring` | Подстрока для будущей фильтрации; пустая отключает фильтр. |

Все элементы обязательны, включая пустой `<filter_substring />`.
Порядок элементов XML произвольный. Регистр имён элементов и логических
значений учитывается. Внешние пробелы и переводы строк в значениях обрезаются.
Неизвестные и повторяющиеся элементы, вложенные теги, атрибуты и посторонний
текст отклоняются.

Правила проверки значений:

- Имя пакета начинается с латинской буквы или цифры, затем разрешены также
  `.`, `_`, `-`. Допускается префикс `@scope/` с теми же правилами для scope.
  Пробелы, версии, пустые компоненты и посторонние символы запрещены.
  Это проверка имени прототипом, а не полная проверка правил публикации npm.
- URL должен иметь схему `http` или `https`, сервер и корректный порт, если
  он указан. Пробелы, логин и пароль в URL запрещены. Доступность сервера
  по сети проверяется при запросе метаданных на этапе 2.
- В тестовом режиме вместо URL требуется существующий читаемый обычный файл.
  Пробелы в имени локального файла разрешены.
- Для выходного файла требуется существующий каталог и доступ на запись.
  Путь не должен указывать на каталог. Расширение `.svg` проверяется без
  учёта регистра в соответствии с форматом изображения варианта 30.
  Файл не создаётся и не перезаписывается.
- Подстрока фильтра должна состоять из печатных символов одной строки.
  Внутренние переводы строк, табуляция и другие управляющие символы запрещены.

Относительные пути `repository` и `output_file` отсчитываются **от каталога
XML-файла**. Абсолютные пути также допустимы. `~` и переменные окружения
внутри XML не раскрываются.

## Получение данных npm

Вариант 30 не задаёт версию пакета, поэтому запрашивается версия с тегом
`latest`: `GET <repository>/<package>/latest`. Имя scoped-пакета кодируется
в URL, например `@types/node` становится `@types%2Fnode`. Путь внутри URL
пользовательского реестра сохраняется; конечный `/` необязателен.
Параметры запроса сохраняются, фрагмент `#...` в HTTP-запрос не передаётся.

Выполняется один запрос с `Accept: application/json` и тайм-аутом 10 секунд
на сетевые операции (`REQUEST_TIMEOUT` в `src/npm.py`). Обработка версий,
установка архивов и запросы метаданных самих зависимостей не выполняются.

Из ответа читаются:

- `dependencies` — обычные прямые зависимости;
- `optionalDependencies` — необязательные прямые зависимости. При совпадении
  имени запись отсюда заменяет запись в `dependencies`, как предусмотрено npm.

`devDependencies` нужны для разработки самого пакета, а `peerDependencies`
описывают требования к его окружению; в данном проекте они не включаются
в список прямых runtime-зависимостей. Транзитивные зависимости не запрашиваются.
Пакеты выводятся по алфавиту с исходными спецификациями версий. Диапазоны,
алиасы `npm:...` и Git-адреса сохраняются без разрешения в точную версию.
Пустая строка спецификации также сохраняется: npm допускает её для любой версии.

Источники описания формата:
[официальный HTTP API реестра](https://github.com/npm/registry/blob/main/docs/REGISTRY-API.md)
и [поля package.json](https://docs.npmjs.com/cli/configuring-npm/package-json/).

## Примеры использования

Запуск с `examples/config.xml` получает прямые зависимости `express`.
Ниже показан фрагмент реального вывода; набор и версии зависят от текущего
значения тега `latest` в реестре:

```text
Прямые зависимости пакета express:
accepts: ^2.0.0
body-parser: ^2.3.0
content-disposition: ^2.0.1
content-type: ^2.0.0
cookie: ^0.7.1
cookie-signature: ^1.2.1
debug: ^4.4.0
...
```

Параметр `filter_substring=debug` на этом этапе не применяется: зависимость
`debug` остаётся в выводе. Аналогично `ascii_tree=true` и `output_file`
пока только проверяются при загрузке конфигурации.

Запуск с `examples/no_dependencies.xml` для пакета без зависимостей:

```text
У пакета is-number нет прямых зависимостей.
```

`examples/scoped_config.xml` демонстрирует получение данных `@types/node`.
`examples/test_config.xml` оставлен как пример конфигурации будущего тестового
режима; на этапе 2 он завершается с кодом `1` и пояснением про этап 3.

Успешное завершение возвращает код `0`. Ошибка конфигурации или аргументов
возвращает код `2`, ошибка получения данных — код `1`. Сообщения ошибок идут
в `stderr`, обычный вывод остаётся пустым. Трассировка исключения не выводится.
Если ошибок несколько, сообщается первая обнаруженная; после её исправления
приложение проверяет конфигурацию заново.

Для сетевого запроса обрабатываются HTTP 404 (пакет или `latest` не найден),
другие HTTP-ошибки, ошибки DNS, отказ соединения, тайм-аут и обрыв ответа.
Некорректный JSON, несовпадающее имя пакета, отсутствие версии и повреждённые
поля зависимостей также приводят к понятному сообщению.

## Демонстрация ошибок

```sh
python3 -B -m tools.demo_errors
```

Команда создаёт временные XML-файлы, поочерёдно меняет каждый параметр,
запускает настоящий CLI и показывает сообщение и код завершения.
Временные файлы автоматически удаляются.

| Параметр | Ошибочное значение | Ожидаемый результат |
| --- | --- | --- |
| `package` | `bad name` | Ошибка имени пакета. |
| `repository` | `ftp://example.org` | Требуется HTTP(S)-адрес. |
| `test_mode` | `yes` | Допустимы только `true` и `false`. |
| `output_file` | `graph.png` | Требуется расширение `.svg`. |
| `ascii_tree` | `1` | Допустимы только `true` и `false`. |
| `filter_substring` | Две строки | Запрещены управляющие символы. |

Например, при `<ascii_tree>1</ascii_tree>`:

```text
Ошибка конфигурации: ascii_tree: допустимы только true или false.
```

Тесты также проверяют пропуск каждого параметра, пустые значения, повреждение
XML, неверную структуру документа, ошибки файлов и путей, порт URL, права
доступа и запуск из другого каталога. HTTP-клиент проверяется на ответах npm,
сортировке, необязательных зависимостях, кодах HTTP и сбоях транспорта.
Автоматические тесты подменяют HTTP-ответы и не требуют доступа к сети;
настоящий запрос проверяется обычным запуском приложения.

## Сборка, тесты и проверка оформления

Отдельная сборка для запуска Python-приложения не требуется. При необходимости
можно скомпилировать исходники в байт-код; он исключён из Git:

```sh
python3 -m compileall -q -b src
python3 -B -m unittest discover -s tests -v
python3 -B -m tools.check_style
```

Автономная проверка контролирует длину строк до 79 символов, строки docstring
до 72 символов, отсутствие табуляции и концевых пробелов, наличие документации,
размер файла до 1000 строк, функции до 40 строк и до 7 аргументов.
Она также оценивает сложность по AST с учётом ветвлений, логических операций
и генераторов; предельное значение — 10. Эта проверка покрывает перечисленные
ограничения и не заменяет полноценный линтер PEP 8.

Имена, отступы, расположение импортов и оформление кода следуют PEP 8.
Константы используются вместо числовых литералов в сравнениях.
Документация функций оформлена docstring.

Для полноценной проверки PEP 8, имён, неиспользуемых импортов и сложности
можно установить отдельные инструменты разработки:

```sh
python3 -m pip install -r requirements-dev.txt
python3 -B -m flake8 src tests tools
```

Настройки находятся в `.flake8`: строки до 79 символов и сложность до 10.
Исключено устаревшее правило W503: перенос перед логическим оператором
соответствует действующим рекомендациям PEP 8. Зависимости разработки
не нужны для запуска приложения, тестов и автономной проверки.

При установленном `make` доступны эквивалентные команды:

```sh
make run
make build
make test
make check
make lint
make demo-errors
```

Переменную `PYTHON` можно передать и в `make`, например `make test PYTHON=python3`.

## Дополнительные проверки конфигурации и оформления

DNS-метки не должны быть пустыми, начинаться или заканчиваться дефисом.
Длина метки ограничена 63 символами, полного имени без конечной точки —
253 символами. Разрешены полное DNS-имя с конечной точкой, localhost, IPv4
и IPv6. Путь каталога вроде `graph.svg/` не принимается за имя SVG-файла.

Публичные интерфейсы модулей `src` объявлены через `__all__`. Внутренние
функции имеют префикс `_`. При чтении XML обработка исключений ограничена
чтением и разбором файла; проверка параметров выполняется отдельно.

Дополнительные функции, настройки и проверки:

| Объект | Назначение |
| --- | --- |
| `MAX_HOST_LENGTH`, `MAX_HOST_LABEL_LENGTH` | Ограничения длины DNS-имени и меток. |
| `_validate_hostname(hostname)` | Проверка структуры и длины DNS-имени. |
| `check_comments(source)` | Ограничение строк комментариев 72 символами. |
| `check_numeric_comparisons(tree)` | Запрет числовых литералов в сравнениях: правило М1. |
| `_is_numeric_literal(node)` | Распознавание чисел с исключением `bool`. |

Для строгой проверки оформления используются необязательные инструменты:

```sh
python3 -m pip install -r requirements-dev.txt
python3 -B -m flake8 src tests tools
make lint
```

В `.flake8` явно задано `ignore = W503`: остальные стандартные исключения
не скрывают проверки. W503 исключён, поскольку перенос перед оператором
соответствует современному PEP 8. Приложение и тесты используют только
стандартную библиотеку; установка инструментов оформления для них не нужна.

## История разработки

Этап 1 сохранён отдельным коммитом с подробным сообщением:
`feat(stage-1): implement validated XML configuration CLI`.
Исправления конфигурации и общих проверок входят уже в этот этап.

Этап 2 сохранён отдельным коммитом с подробным сообщением:
`feat(stage-2): fetch direct npm dependencies`.
Исправления первого этапа наследуются без отдельного коммита исправлений.

Публикация в удалённый репозиторий выполняется отдельно.
